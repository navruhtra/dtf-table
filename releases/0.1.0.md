# DTF Table 0.1.0

The first public release of the DTF Table: print files for
direct-to-film printing, in the browser. It writes files your RIP
loads; it does not drive a printer.

- Alpha repair: soft edges are cut, and fades, glows and shadows
  become halftone dots, so no pixel is half clear.
- A white layer, choked so a small misregistration shows no white
  rim. Thin lines keep their white. Spread, density, knockouts and
  colours printed with no white.
- Machine profiles: a 13, 22 or 24 in roll or a custom one, the
  longest print, the file resolution and how your RIP takes white.
- Gang sheets packed onto your roll width, written in bands so a
  22 × 100 in sheet at 300 dpi never sits in memory whole. PNG,
  TIFF or PDF at size, plus a separate white file.
- Preflight: resolution at print size, size against the roll, lines
  and gaps under 0.5 mm, and the semi-transparent pixels alpha
  repair will fix.
- Nothing is uploaded: the art stays in your browser tab.

## Use it

Open
https://americandreamnetwork.us/tools/printing/dtf-transfers/dtf-table
in a browser. Nothing to install.

To run it yourself: `npm run setup`, then `npm start` (README,
Run it locally).

## Checks in this release

- Unit tests for alpha repair, the white layer, machine profiles,
  nesting, the sheet writers and preflight; the browser deflate
  writes the same files as Node's.
- The benchmark gate against `benchmark/baseline.json`, with
  rectpack 0.2.2 as the nesting competitor.
- A browser test of the page at 390 × 844 and 1280 × 800, alone and
  framed as on the ADN site.

## Checksums

`src/vendor.sha256` holds the SHA-256 of every file `npm run setup`
downloads, as pinned in `scripts/vendor-pins.mjs`, including the
Separation Table engine at commit 00e00bb. Check a copy with
`sha256sum -c vendor.sha256` in `src/`, or
`node scripts/notices.mjs --check`. Third-party licenses:
THIRD-PARTY-NOTICES.md.

## Known limits

- Every quality number is a model number until the test targets are
  printed and measured.
- Whether a RIP keeps a white file you supply, or makes its own,
  differs by RIP and setting. It is not checked yet.
